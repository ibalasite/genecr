# 儲值刮刮樂 SCRUM 故事卡

## Epic：儲值/遊戲贈刮刮券 + 週抽幸運代號
老玩家每儲值1000送1張刮刮券，遊戲中亦會掉落刮刮券。刮中可獲 20-5000 倍獎金；未中獎之券保留幸運代號參與每週幸運抽獎。整體 RTP 與每日發放上限受代理商保護機制嚴格控管，確保不造成代理商損失。

**總計**：10 張故事卡，預估 47 點。

---

## 🏗️ 基礎建設

### Story #1：建立刮刮樂後端服務骨架
**作為** 後端工程師，**我想要** 建立 Node.js + Express service 含 MySQL 與 Redis 連線，**以便** 所有刮刮券 API 都掛在此服務下統一管理

**驗收標準**：
- [ ] 服務可由 npm start 啟動並通過 /healthz
- [ ] MySQL/Redis 連線設定可由環境變數覆寫
- [ ] 連線失敗時有 retry 與告警 log

- **Story Points**：3
- **負責團隊**：`Server`- **技術備注**：Express + mysql2 + ioredis，使用 dotenv 管理連線設定

---

### Story #2：刮刮券資料表與索引設計
**作為** 後端工程師，**我想要** 建立 scratch_ticket、scratch_prize_pool、weekly_draw、agent_budget 等資料表，**以便** 支援券發放、兌獎、週抽與代理商損益追蹤

**驗收標準**：
- [ ] scratch_ticket 含 lucky_code 唯一索引
- [ ] prize_pool 支援機率與每日上限欄位
- [ ] 週抽結果可追溯至 ticket_id 與 agent_id

- **Story Points**：5
- **負責團隊**：`Server`- **技術備注**：MySQL 8 + Sequelize migration，lucky_code 8 碼英數

## 🎮 遊戲邏輯

**作為** 後端工程師，**我想要** 監聽儲值事件，每滿 1000 點發 1 張刮刮券，**以便** 老玩家儲值即享回饋

**驗收標準**：

## 🏆 獎勵系統

### Story #5：刮刮券兌獎邏輯與 RTP 控管
**作為** 後端工程師，**我想要** 提供刮券 API，依 prize_pool 抽出 20-5000 倍獎項或未中獎，**以便** 確保獎項分佈符合預期 RTP

**驗收標準**：
- [ ] 抽獎結果加密簽章不可竄改
- [ ] 每日獎金池上限觸及時自動轉為未中獎
- [ ] 未中獎券保留 lucky_code

- **Story Points**：8
- **負責團隊**：`Server`- **技術備注**：加權隨機 + Redis 原子扣減每日預算

---

### Story #6：代理商損益保護機制
**作為** 後端工程師，**我想要** 依代理商當期淨收入動態調整實際派彩上限，**以便** 確保任何代理商不因活動虧損

**驗收標準**：
- [ ] 每位代理商有獨立 budget cap
- [ ] 派彩超過 cap 時自動降級為未中獎
- [ ] 後台可查看代理商損益儀表板

- **Story Points**：5
- **負責團隊**：`Server`- **技術備注**：Redis 即時計數 + 每分鐘 MySQL 落地

---

### Story #7：每週幸運代號開獎
**作為** 後端工程師，**我想要** 每週固定時間從未中獎券中抽出幸運兒，**以便** 未中獎玩家仍有期待感

**驗收標準**：
- [ ] 排程於每週日 22:00 執行
- [ ] 抽出結果公告且不可重抽
- [ ] 得獎獎金納入代理商損益核算

- **Story Points**：5
- **負責團隊**：`Server`- **技術備注**：node-cron + MySQL 交易鎖；Redis pub/sub 通知
